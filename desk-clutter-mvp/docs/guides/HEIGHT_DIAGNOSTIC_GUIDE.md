# 空桌高度诊断：先定位远端误检，再决定怎么修

独立入口 `desk_height_diagnostic.py`，复用 v04 的标定坐标与网格定义。
它只测量和保存，不更改 `calibration.json`、基线或 v04 检测逻辑，不自动纠正高度。
这里的“高度”是相对当前标定平面的有符号距离，不是真实高度的独立测量。

## 这次怎么用

1. 退出 v04 / v2，释放相机。保持相机、桌面和照明不动。
2. 尽量清空整张桌面；至少确保左上远端误检区及附近确实没有物体。留着电脑等物品也能采集，
   但物体位置的正高度不能解释成桌面偏差，也不能据此给整张桌面建立背景补偿。
3. 在项目目录的现有环境运行：

   ```bash
   .venv/bin/python desk_height_diagnostic.py
   ```

4. 程序先显示实时单帧预览，便于核对位置。准备好、手移出画面后按 **C**，固定场景采集约 **5 秒**。
   采集中仍显示当前帧，尚未显示整段统计；结束后画面冻结为统计结果并自动保存。
5. 在任一栏中点击原来左上角误检的位置；三栏会同步出现十字，底部显示该格的具体数值。
   再按 **S** 保存含选点的报告。把新目录中的 `report.png` 和 `summary.json` 发回来即可。
6. **C** 可重新采集一段独立记录；不会把两次混在一起。**Q / Esc** 退出。
   采集中再次按 C 无效；采集未完成就退出不会保存那段未完成数据。

结果保存在脚本目录下：

```text
height_diagnostics/
  height_YYYYMMDD_HHMMSS_microseconds/
    report.png
    summary.json
    samples.npz
```

终端打印完整保存路径。每次自动保存和按 S 都创建新目录，不覆盖旧结果。
截图不包含 RGB；报告也没有保存原始全分辨率深度帧或原始点云。

## 三张图分别表示什么

| 图 | 统计含义 | 看什么 |
| --- | --- | --- |
| 左：Height median | 每帧每格先取高度中位数，再对整段有效帧的中位数取中位数 | 空桌是否持续偏高或偏低；红色为正、蓝色为负、近白色接近零 |
| 中：Temporal spread | 同一格的逐帧高度中位数，取 P90−P10 | 整段中来回变化的幅度；越黄/红幅度越大，不是标准差或误差界限 |
| 右：Observed frames | 每格点数达到最低要求的帧数 / 实际收到并采集的帧数 | 是否经常缺测；绿色多观测，紫色少观测，不代表测量准确率 |

当前默认每格至少 3 个有效点，才产生该帧的高度样本。
最终高度/波动要求 **至少 10 个有效帧，且占采集帧数至少 50%**，否则显示灰色、数值 `N/A`。
这些只是防止样本过少的初始门槛，不是经过硬件验证的精度标准。
右侧覆盖率即使不足 50% 仍会显示，避免把“没看到”误读为“很稳定”。

选点后还显示：

- `Within-frame P90-P10`：每帧同一格内各点的高度分散范围，再对有效帧取中位数。
  即使格子的中位高度很稳定，格内也可能存在异常高点或混合表面；这项可帮助发现这种情况。
- `Object-supported / observed frames`：有效帧中，符合 v04 物体点数/占比条件的帧比例。
  默认是至少 3 个点、占该格采样点至少 60%，且高度在 10–400mm 之间。
  **尚未执行边缘排除或 3/5 时间投票，不等于 v04 最终稳定占用率。**
- `ACTIVE / EXCLUDED by v04`：该格是否位于 v04 的内缩检测区内。诊断两者都会测量。

黄色是原标定边界，青色是 v04 的有效检测边界。与 v04 的紫色排除带不同，
**诊断没有屏蔽那条带的高度**，否则会把正在寻找的问题遮住。
视图上下方向与 v04 一致；底层数组行号与屏幕上下方向相反，点击转换由程序处理。

左图颜色显示范围为 −30 至 +30mm，中图为 0 至 20mm；超出范围只截断颜色，
底部数字、JSON 和 NPZ 均保留未截断的值。`--min-height-mm` 只是物体支持率的参考下限，
不是高度采样下限：负高度、低于 10mm 和高于 400mm 的高度仍参与诊断。
有效深度范围仍沿用 v04 的相机 z=0.15–2m；非有限值、零深度及范围外点会被丢弃。

## 怎么解读，不要直接下结论

- 确认是空桌面，且**覆盖率足够、中位高度持续偏高、时间波动较小**：支持“相对当前标定存在持续偏差”，
  下一步检查标定平面/相机位置以及深度测量的固定偏差；不能仅凭这张图认定一定是标定错了。
- **时间波动明显**：考虑动态噪声或场景变化。先确认没有移动物体、手、相机及照明变化，再讨论滤波与迟滞阈值。
- **时间中位数较稳，但格内分散大或物体支持率异常**：不能只看中间那张图，需考虑混合表面/异常点等可能性。
- **覆盖率低**：目前证据不足，不能说该处空、平或稳定。缺测从不补成零高度。

固定偏差、时间波动和缺测可以同时存在。P90−P10 不包含全部极端值；原始逐帧网格统计保存在 NPZ，
可继续分析。这里没有平面重新拟合、自动原因分类、像素级精度保证或自动背景补偿。

若固定照明后仍有全桌趋势性的高度偏差，可另用
[多帧空桌平面标定](MULTIFRAME_CALIBRATION_GUIDE.md) 生成候选，再通过新采集的数据验证。
这是独立入口，不会修改本诊断脚本或自动替换原标定；需要先清空整个 ROI。

## 参数与离线检查

```bash
# 时间可设为 1–30 秒；真实采集按时钟计时，不假定处理达到 30 FPS
.venv/bin/python desk_height_diagnostic.py --seconds 5

# 若 v04 使用了其他参数，诊断中也显式指定同样的值
.venv/bin/python desk_height_diagnostic.py --grid-mm 10 --min-height-mm 10 --edge-margin-mm 20

# 无相机、无 GUI：保存带“合成数据”标记的演示后退出
.venv/bin/python desk_height_diagnostic.py --demo --output-dir /tmp/desk-height-demo

# 仅诊断测试，或包括 v04 的全部测试
.venv/bin/python -m unittest discover -s tests -p 'test_height_diagnostic.py' -v
.venv/bin/python -m unittest discover -s tests -v
```

`--edge-margin-mm` 只改变诊断图中青色参考边界，不屏蔽采样。
`--min-cell-points` 默认 3。完整参数见 `--help`。
依赖与 v04 一致：NumPy、带桌面窗口支持的 OpenCV；真实相机模式另需 pyrealsense2。

`summary.json` 含参数、原标定几何及 SHA-256、所有统计网格和选点信息；无效统计使用 JSON `null`。
`samples.npz` 可用 `np.load(path, allow_pickle=False)` 打开，包含相对时间戳和逐帧网格：
`median_mm`、`spatial_span_mm`、`point_counts`、`object_support`，维度为 `[帧, 行, 列]`。
它不包含被丢弃点的高度，也不包含每个采样点的原始高度，不能替代相机原始录制。

合成演示含固定 +20mm 区、±12mm 交替变化区、−15mm 区及低覆盖区。
它仅用于检查软件流程，不能证明真实相机的噪声、偏差或帧率。
