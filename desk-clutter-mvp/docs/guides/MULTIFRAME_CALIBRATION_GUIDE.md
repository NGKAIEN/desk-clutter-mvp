# 多帧空桌平面标定与独立验证

入口：`desk_calibrate_multiframe.py`。这是对已有四角标定的小幅平面修正，不是重新识别桌面。
目标是检查远端空桌偏高能否通过更稳健的参考平面改善。它不消除深度时间噪声，
不修改 PCA、物体高度阈值、边缘排除、时间投票或聚类算法，也不计算整洁指数。

## 本次怎么用

1. 退出 v04、旧高度诊断等占用相机的程序。
2. 保持相机和桌子不动，保留台灯不直射桌面的设置，等待画面稳定。
3. **清空整个黄色 ROI 内的物品**，包括电脑、手机、线材等；不只是清空两个问题区域。
   无法清空时先不要标定，拟合算法不能保证分辨平坦物体和桌面。
4. 启动：

```bash
cd desk-clutter-mvp
.venv/bin/python desk_calibrate_multiframe.py
```

窗口获得焦点后，按下列顺序操作：

| 操作 | 发生什么 |
| --- | --- |
| `C` | 采集约 5 秒空桌数据，拟合并单独保存候选标定。成功后画面停在拟合结果。 |
| `V` | 候选保存后，再采集约 5 秒新数据，用同一批新点分别计算旧/新平面高度，保存独立验证。 |
| 点击任意栏 | 三栏同步选中同一格，底部显示该格的新旧高度、时间波动、覆盖率、物体支持比例。 |
| `S` | 保存当前选点截图；拟合和验证的基础报告已自动保存，不按 S 也不会丢失。 |
| `Q` / Esc | 退出并释放相机。 |

采集中不要移动物体、相机或灯，也不要把手伸入 ROI。采集时 C/V/S 不执行；Q 仍可退出。
再次按 C 会开始新一轮拟合，不覆盖已保存结果；再次按 V 会生成另一份独立验证。
本轮没有候选时按 V 只会提示先按 C。程序重启后需重新 C、V，不支持恢复上次候选到验证窗口。

若出现 `FIT REJECTED`，查看终端原因，不会保存失败的候选。常见原因是帧数不足、
可靠点不够或集中在局部、平面一致性太低、需要的修正过大。不要直接放宽安全门限来强行通过。

## 三栏怎么看

- 左栏：原标定下的高度中位数。
- 中栏：候选标定下的高度中位数。
- 右栏：候选标定下的时间 P90−P10；越偏黄红，逐帧波动越大。

高度图中，白色接近参考平面，红色高于平面，蓝色低于平面；**红色不是物体分类结果**。
灰色表示没有足够观测，不能当成零高度。颜色范围只影响显示，报告保留真实数值。
采集中的图是当前帧预览，尚没有多帧时间统计；完成后才显示本段采集的统计图。

按 C 后：中栏是拟合数据按网格中心近似校正的图，只能说明拟合结果，不能当作效果验证。
按 V 后：中栏来自新采集的原始点对候选平面的精确距离，不重复使用 C 的数据，也不再重新拟合。

重点点击之前左上远端误检处，并检查：

1. 独立验证里，中栏该区域是否比左栏更接近 0mm，而不是整体变成明显负高度。
2. 桌面其他区域有没有一起变差，右下区域是否仍正常；同时比较全区绝对高度中位数和 P90。
3. 覆盖率是否足够，不能把缺测变多误认为改善。
4. 时间波动是否仍然很大。**平面调整可以修正整体偏差，不保证减少时间波动**；若偏差改善但仍闪烁，再单独考虑滤波。
5. `Object-supported frames` 是满足点数与高度支持条件的帧数 / 有效观测帧数，
   不是 v04 经时间投票后的占用率，也不是整洁分数。

显示和全区对比固定使用旧 UV 网格及旧有效 ROI，避免换了检测范围导致比较失真。
因此黄色/青色线是旧边界参考，不是候选标定的新边界。实际 v04 使用候选时会按新的坐标系建立网格，
仍需要进行一次空桌及放物体检查，特别是桌边位置和 PCA 角度。

## 保存在哪里，发哪些文件

默认目录在项目下，每次拟合一个独立目录：

```text
plane_calibrations/plane_时间戳/
  original_calibration.json     原标定的逐字节备份
  candidate_calibration.json    候选，未自动启用
  fit_report.json               拟合门限、样本数、残差、统计网格
  fit_samples.npz               拟合采集的逐帧网格统计
  fit_comparison.png
  validation_时间戳/
    validation.json            独立验证、几何信息、候选文件 SHA-256
    comparison.png
    samples_original.npz       同一批新帧，旧平面计算
    samples_candidate.npz      同一批新帧，候选平面计算
    selected_时间戳.png         可选，S 保存的选点画面
```

这次先提供 **validation 子目录里的 `comparison.png` 和 `validation.json`**；
最好再点远端红点位置按 S，附上选点截图。不要只发 fit_comparison.png。
终端会打印完整保存路径。JSON 中无效值是 null；NPZ 中是 NaN，加载请用 `allow_pickle=False`。
NPZ 保存的是逐帧网格统计，不包含逐个原始深度点，不能替代相机录制文件。

## 确认效果后才试用候选

**原来的 `calibration.json` 始终没有被写入，候选也不会自动启用。**
确认独立验证后，退出标定程序，在 v04 中显式传入终端给出的候选文件路径，例如：

```bash
# 将时间戳替换为你本次生成的实际目录名
.venv/bin/python desk_orientation_v04.py --calibration plane_calibrations/plane_时间戳/candidate_calibration.json
```

不带 `--calibration` 运行 v04，就仍然使用原来的 `calibration.json`，不需要覆盖文件再回滚。
此版本不提供自动通过判定；验证 JSON 与候选文件的 SHA-256 对应，后续不要手动编辑候选后继续引用旧验证。
即使已经做了 V，候选文件仍保留 `candidate_only` 标记；独立验证结果保存在单独报告里。

## 原理及保护条件

1. 用旧坐标系把点分到 10mm 网格。每帧每格至少 3 点，取高度中位数。
2. 对每格再取多帧中位数。拟合时每格等权，避免近处密集点独占权重。
3. 只在旧有效 ROI 内选择可靠样本：至少采集 30 帧，该格覆盖率至少 80%，
   高度绝对值不超过 30mm，时间 P90−P10 不超过 20mm。
4. 拟合 `h = a*u + b*v + c`，单位均按米计算；使用固定随机种子的 RANSAC，
   再用限定在 6mm 残差内的 Huber 加权细化（Huber 尺度 3mm）。至少 65% 入选格支持同一平面。
5. 入选格至少覆盖有效 ROI 的 50% 且不少于 100 格；内点至少覆盖 40%。
   还检查两个坐标方向的跨度以及四个象限的支持，防止从一小块桌面外推整张桌子。
6. 修正倾角超过 3°，或任一旧 ROI 角点处的高度修正超过 30mm，就拒绝这次细化。
   这些是本原型的保守保护值，不是相机精度保证，也不是物体检测阈值。
7. 同时更新平面、原点、正交坐标轴和四角 UV。沿原四角的深度相机射线与新平面求交，
   保留角点投影位置，不是只改法向量后沿用过期 UV。它不会自动找回真正的物理桌角。
8. 候选移除旧 `baseline`，因为它属于旧平面/ROI；原文件中的基线不动。

本方法假设已有标定大体正确，桌面足够平且已经清空。它不能修复错误四角、相机移动、
强烈局部反光/深度错误、缺测、桌面翘曲，也不能保证发现占据很大面积的平坦物品。
若需要大幅修正，应回到原来的四角标定流程，并先自行备份原标定。

## 离线演示和测试

```bash
# 无相机、无 GUI，生成合成拟合和独立验证后退出；不是实际桌面标定
.venv/bin/python desk_calibrate_multiframe.py --demo --seconds 3 --output-dir /tmp/desk-plane-demo

# 新工具测试 / 全部回归测试
.venv/bin/python -m unittest discover -s tests -p 'test_multiframe_calibration.py' -v
.venv/bin/python -m unittest discover -s tests -v
```

支持 `--calibration`、`--seconds`（3–15 秒）、`--grid-mm`、`--edge-margin-mm`、`--output-dir`。
默认 5 秒、10mm 网格、20mm 边缘排除；点数和物体支持参考沿用 v04 默认的 3 点、60%、10–400mm。
本轮不要通过调整这些参数同时引入其他变量。真实采集按经过时间计时，不假定处理能达到 30 FPS。
依赖：NumPy、带窗口支持的 OpenCV；实时模式另需 pyrealsense2。复用同目录 v04 和高度诊断模块。

合成演示包含已知小角度倾斜、随机高度噪声、随机缺测及局部异常点。
合成改善仅验证软件计算流程，不代表真实设备测量效果；需要你在现场按 C、V 采集后判断。
