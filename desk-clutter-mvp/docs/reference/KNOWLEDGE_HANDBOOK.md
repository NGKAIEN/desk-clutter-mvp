# Desk Clutter MVP｜知识点手册

从深度点到可信的桌面状态｜截至 2026-11-01

本手册围绕本项目实际用到和讨论过的知识展开，不是计算机视觉百科。
默认实现以 v04 核心、v05 面板、可选局部空桌参考为准；旧版和未实现方案单独标注。
公式中的 m 为米、mm 为毫米；除特别说明，位置和角度属于桌面坐标系，不是 RGB 像素坐标。

## 建议阅读顺序

| 学习阶段 | 章节 | 你应能回答 |
| --- | --- | --- |
| 理解数据 | 01-04 | 像素、点、平面、俯视网格怎样对应？ |
| 理解误差 | 05-08 | 为什么降阈值噪点更多？为何有数据仍会漏检？ |
| 理解区域 | 09-10 | 一个区域为何不一定是一个物体？N/A 为何合理？ |
| 理解产品 | 11-12 | 空闲分是什么？如何证明改动有效？ |
| 理解实现 | 13-15 | 从哪里调参、怎样排错、怎样复现与发布？ |

## 总链路

深度帧 → 点云 → 有效深度过滤 → 桌面高度/UV → ROI 网格 → 单帧证据 → 时间稳定 →
稳定占用 → 两条独立输出：空间占用指标，以及连通区域/PCA。

局部模式在分类前增加：单格高度中位数 → 减空桌偏差 → 短时高度中位数 → 单格噪声门槛。
它不使用旧的绝对高度下限/60%支持规则；ROI、状态票、区域、PCA 和分数定义仍复用。

核心原则：先确认测到了什么，再讨论怎样分类；先证明区域可信，再解释角度；
未知不是空闲，稳定不等于准确，训练拟合不是独立验证。

# 01｜深度相机、点云与坐标系

## 深度不等于桌面上方高度

相机深度描述相机坐标里的位置。桌上物体高度则是点到桌面参考平面的有符号距离，
不能直接把深度像素值与 3mm/10mm 比较。斜看桌面时，桌子近端和远端的深度本来就不同。

在无畸变针孔近似下，像素 (px,py) 和深度 Z 可反投影：

```text
X = (px - cx) * Z / fx
Y = (py - cy) * Z / fy
P = [X, Y, Z]
```

fx/fy 是以像素为单位的焦距，cx/cy 是主点。实际相机需处理畸变，应使用 SDK 提供的标定与投影接口，
不要把简化公式当全部相机模型。RealSense 的流有各自坐标系，单位为米，通常 x 向右、y 向下、z 向前。
参考：[RealSense 投影文档](https://dev.realsenseai.com/docs/projection-in-realsense-sdk-2-0/)。

## RGB 和深度不是天然同一视角

内参把像素与本相机射线连接起来；外参把不同相机坐标系连接起来：`P_color = R * P_depth + t`。
深度点纹理映射到彩色图需要转换/投影。遮挡边界可能出现一侧可见、另一侧不可见，
不能因叠层对不齐就直接断言桌面平面错了。

项目通过 pyrealsense2 获取点云。当前默认采集设置为 640×480 深度流、请求 30FPS，
但实际处理帧率受设备、计算和 GUI 影响；5秒采到103帧不等于30FPS。
有效点要求有限数值且相机深度处于0.15-2m；无深度、NaN、零值不转成空桌点。

代码定位：desk_height_diagnostic.camera_source、frame_grid；旧照片映射在 desk_compare_view。

# 02｜平面、RANSAC 与多帧细化

## 有符号高度

平面写作 `n·P + d = 0`，n 为单位法向量。高度 `h = n·P + d`；若 n 未归一化，需除以其长度。
符号方向必须统一，项目使桌面朝相机一侧的物体为正高度。误差1mm写成0.001m，避免单位错千倍。

RANSAC 随机选择最小样本拟合，再统计残差小于门限的内点，寻找大一致集。
三点确定平面时要求不共线。它能减轻离群点影响，但“支持最多的平面”可能是墙面，
不是语义上的桌子。RANSAC 的平面内点阈值也不等于物体高度下限。
参考：[Open3D 平面分割](https://www.open3d.org/docs/release/tutorial/geometry/pointcloud.html#plane-segmentation)。

## 为什么多帧、每格等权

近处点通常更密，直接把所有点等权拟合可能让近处占主导。项目先取每帧单格高度中位数，
再对每格取时间中位数，拟合时每格等权。当前细化不是重新找桌，而是拟合旧坐标中的小趋势：

```text
h(u,v) = a*u + b*v + c
```

a/b 对应倾斜趋势，c 对应偏移。RANSAC 后用有界 Huber 权重减弱较大残差：
小残差权重1，较大残差随残差倒数减小，超过内点带则权重0。
实现还做坐标中心化/尺度归一和条件数检查，避免退化样本的数值问题。

保护条件包括至少30帧、单格覆盖80%、时间跨度≤20mm、绝对高度≤30mm；
足够网格/空间跨度/四象限支持，以及最大3°倾角和30mm角点修正。
这些是本项目保守参数，不是行业相机精度标准。

重要：更换平面时必须同步更新原点、正交轴和角点UV；只改 normal 会让几何自相矛盾。
新候选移除旧占用率 baseline，但不改原文件。代码：desk_calibrate_multiframe.fit_plane / candidate_calibration。

# 03｜桌面 UV、照片选角与俯视图

## 从三维到桌面二维

在桌面平面取原点 O 和两条互相垂直的单位向量 e_u、e_v：

```text
u = (P - O)·e_u
v = (P - O)·e_v
桌面平面上的点：P_plane = O + u*e_u + v*e_v
```

俯视图 BEV 是桌面坐标的栅格表示。它不是额外一台俯拍相机，不能看见遮挡后的物体。
把显示画布旋转/翻转，只改变呈现方向，不改变物体相对桌边的真实角度。

## 在照片中选桌角

先将彩色像素反投影为射线，再经相机外参转换到深度坐标。若射线起点 C、方向 r，
则 `P=C+t*r` 与平面交点满足：

```text
t = -(n·C + d) / (n·r)
```

分母近零说明射线近乎平行，t≤0 表示交点在相机后方，应拒绝。使用桌面假设求交，
可以绕过桌角处单个深度像素缺失，但无法纠正已经拟合错的平面。

四角应是无重复、非退化、顺序一致的凸四边形。错误/交叉角点会污染ROI与长边参考。
左右图用同一角点编号和鼠标联动，解决“右图到底是哪一块”的可解释性问题。

## 展开照片的限制

桌面纹理可由平面映射展开，高于桌面的电脑会偏移或拉伸。把照片展开得漂亮，
不等于生成了正确的高物体俯视轮廓。缺少源照片覆盖的区域也不能随意补成真实纹理。

代码定位：desk_compare_view 的投影/射线与视图函数；desk_debug_v2 的标定与角点检查。

# 04｜网格、ROI、边缘和物理单位

对边长 g 的网格，索引用向下取整：

```text
col = floor((u-u_min)/g)
row = floor((v-v_min)/g)
```

不能用截断代替 floor：微小负坐标截断可能变成0，错误落入首格。
先检查数组范围，再检查多边形 ROI；边缘处还需 active_mask 屏蔽。
g=10mm 时单格面积100mm²=1cm²，所以629个占用格表示629cm²检测面积，不是体积。

## 网格不是越小越好

更小的网格提高表示分辨率，却减少每格点数、放大缺测/碎裂、增加计算量。
更大网格可能连接相邻物品、平滑细节和改变量化面积。网格只改变表示，不提高相机物理精度。
对比阈值前先固定网格，不要同时改变两个变量。

## 20mm 内缩不是像素腐蚀

当前沿四边计算物理半平面距离，并考虑格子的半宽投影，保证保留格四个角都在内缩内部。
旋转桌面或改变网格后仍以毫米为准，比固定删两行/两列更明确。
排除带在分类、时间稳定、统计、区域和 PCA 中都必须一致屏蔽。

| 区域 | 含义 | 是否进入分数 |
| --- | --- | --- |
| 原 ROI 内、active 内、已知 | 有当前/稳定分类的可检测区域 | 是 |
| active 内、未知 | 当前无法可靠判断 | 不算空闲；占未知比例 |
| 原 ROI 内、排除带 | 主动缩小检测范围 | 不参与分母，不能当空闲 |
| ROI 外 | 非目标区域 | 否 |

代价：真实边缘物体也会被排除，跨边界物体形状可被截断。排除后占用率变了不等于桌面变整洁。
代码：desk_orientation_v04.table_from_data / inset_mask。

# 05｜高度阈值、点支持与三态分类

## 默认绝对模式

先筛选相机深度，再计算平面高度。单点高度在10-400mm之间为物体候选。
单格至少3个物体点且占该格有效点数≥60%，才产生占用证据；桌面证据也需要点支持。
原始栏更敏感，稳定流程使用支持后的 evidence，二者不可混为同一判定。

当物体阈值降低到桌面容差以内时，一个点可能满足两种数值条件。
实现必须让物体点和桌面点互斥，不能同一点同时投两种票。稀疏或冲突不足以确认时保留 UNKNOWN。

## 为什么3mm会出现噪点

高度可近似理解为：真实高度 + 平面偏差 + 局部测量偏差 + 随机波动。
如果空桌高度已经在±数毫米波动，3mm阈值会频繁被空桌越过；如果物体表面的有效高度
因负偏差只有4mm，10mm阈值又会漏检。不存在一个无需测量就保证所有位置正确的全局阈值。

本项目有电脑的选中格：中位4.20mm，时间P90-P10=8.83mm，覆盖100%，
原10mm物体支持帧比例只有7.09%。这说明“观测存在”与“能通过物体条件”不同。

## 三种状态必须分别保存

- FREE：有足够符合桌面的证据。
- OCCUPIED：有足够符合物体的证据。
- UNKNOWN：缺测、过稀、冲突、异常高度或参考无效，不知道，而不是没有物体。

不能把零深度写成0mm桌面高度，不能把 NaN 在统计前全部填零。
局部模式的单格中位数判定替代本页60%点支持规则，具体见第08章。
代码：desk_orientation_v04.make_observation；desk_height_background.LocalHeightDetector。

# 06｜偏差、随机噪声、缺测与照明

## 先区分三种问题

| 现象 | 应测什么 | 优先排查 |
| --- | --- | --- |
| 空桌同位置持续偏红/偏蓝 | 高度时间中位数 | 平面、局部偏差、固定反射/材质 |
| 红绿不停切换 | 单格时间P90-P10 | 阈值附近波动、时间稳定、机位振动 |
| 灰/黑频繁出现 | 有效帧比例、每格点数 | 遮挡、采样稀疏、无效深度 |
| RGB很亮但深度异常不明确 | 同条件深度诊断 | 不把彩色曝光直接当深度故障结论 |

中位数对少数极端值更稳健，但不能消除长期系统偏差。
P90-P10 描述中间80%样本的范围，不是最大误差、标准差、准确率或置信区间。
时间跨度比较同格跨帧中位数；帧内跨度比较同一帧该格不同点。二者反映不同问题。
大跨度还可能来自物体移动，不一定都是传感器噪声。

覆盖率=达到采样条件的帧数/本次收到的帧数，不表示每个样本准确，
也不包含相机本应输出但没被接收的帧。覆盖图绿色可与高度图异常同时出现。

## 台灯对照应怎么做

固定相机、桌面、物体和参数，只改变台灯照射方向；等待稳定再采5秒。
对比同一区域的高度中位数、时间波动和覆盖，不只看RGB照片亮暗。
本项目不直射后右下异常减轻、远端时间波动仍大，支持“光照条件有关”，
不足以单独确定曝光、反射或材质机制。

远处点不稳也不能只凭距离定因；密度、视角、材质、照明和测量模型都可能参与。
本版未承诺自动光照补偿，先保持固定、适合演示的环境。代码：desk_height_diagnostic.Capture。

# 07｜时间滤波与状态投票不是一回事

## 两个层次

数值滤波先处理连续高度，再分类；状态投票先分类，再统计标签。
如果高度长期低于阈值，标签一直是 FREE，延长标签投票不能使其自动成为物体。

当前状态稳定：最近5帧，3票确认 FREE/OCCUPIED，UNKNOWN不投空桌票；
缺测/冲突可短暂保留已知状态，最后得到同类证据超过0.5秒则转未知。
用单调时间戳计算年龄，不把“15帧”硬当0.5秒。

局部高度模式额外用最多5帧高度中位数，至少3个有效样本、年龄≤0.25秒，
且当前帧必须有有效高度。缺当前数据时不从历史填出一个新的高度观测。
两个重叠窗口的输出相关，3/5票不能解释为3个统计独立实验。

## 稳定与延迟的交换

- 中位数可抑制孤立尖峰，但持续偏差仍在。
- 更长窗口可能减少跳动，却增加放入/拿走响应时间。
- 历史保留过长可能产生残影；过短可能频繁未知。
- 当前质量指标要与历史状态分开，避免“画面很稳但数据已失效”。

RealSense SDK 另有像素级空间、时间和补洞滤波；时间滤波依赖历史，可能产生拖影。
它们并非本版已启用的同名模块，不能把自写网格投票叫作 SDK 深度滤波。
参考：[RealSense 后处理](https://dev.realsenseai.com/docs/post-processing-filters/)。

操作：T默认ON，首次按是关闭；局部模式关闭两层时序。R清历史；暂停恢复重新积累。
代码：desk_orientation_v04.TemporalGrid；desk_height_background.HeightMedian。

# 08｜局部空桌参考与自适应门槛

## 先校正同格偏差，再判断变化

记 b_i 为第i格空桌多帧高度中位数，h_i,t为当前单帧单格中位数：

```text
delta_i,t = h_i,t - b_i
filtered_i,t = 最近有效 delta 的短时中位数
gate_i = max(6mm, Q99(abs(滤波后的空桌残差)) + 2mm)
```

例：空桌−4mm，放物体后+4mm，变化为8mm。这解释了为什么绝对4mm不通过10mm，
局部变化却有可能通过6mm。它仍是测量差值，不是经过真值校准的物理厚度。

每格先要求≥3点；滤波后高于本格gate且低于400mm为占用。
非占用且绝对相对高度<10mm才为空桌，其他未知。门槛高的位置也可能漏掉8mm物体。

## 参考质量保护

至少60帧；单格覆盖≥90%；滤波有效帧≥max(30,75%采集帧)；偏差绝对值≤20mm。
噪声门槛>12mm的格不启用，整张active ROI有效参考需≥90%。这些值由HeightPolicy定义。
当前参考没值的格不能在运行时强行设为“0偏差”。

参考只在操作者明确清空ROI并按C时生成，不在运行中持续更新，避免把静止电脑慢慢吸收成桌面。
稳定薄物体可能通过数值筛选，所以“成功保存”不是自动确认空桌。

## 防止误用

绑定标定完整字节SHA-256、网格、内缩和采样设置；普通诊断JSON、有电脑的采集或合成参考不能直接作为LIVE参考。
修改标定排版也会改变哈希；相机移动但文件没变则哈希无法发现，需要操作者重新标定。
Q99是训练分位数，不是未来99%正确保证；必须另测空桌、放物体和拿走。

代码：fit_reference、validate_reference、LocalHeightDetector。参数见 guides/BACKGROUND_HEIGHT_GUIDE。

# 09｜区域、形态学与聚类的边界

## 已实现：二维8邻域连通区域

对稳定占用格进行连通标记，水平/垂直/对角接触算连接。按面积过滤，计算区域轴与框。
默认最小区域8cm²；面积门槛只控制区域/PCA输出，不从分数里删除小占用格。
编号是当帧区域标签/显示顺序，不是跨帧物体身份。

一个电脑可以因缺口分成多个区域，多个接触物品也可以成为一个区域。
“2个候选区域”不能直接说“2个物体”。先检查物体区域内部为何被分类为桌面/未知，再考虑合并。

| 方法 | 能做什么 | 风险 / 本项目状态 |
| --- | --- | --- |
| 开运算 | 去掉小凸起和孤立点 | 可抹掉细物体；v03试用，v04/v05主链路未用 |
| 闭运算 | 连接小缺口、填小洞 | 可能合并不同物体、抬高占用面积；v03试用 |
| 连通区域 | 已有网格上的邻接分组 | 主链路已实现，不识别类别 |
| DBSCAN | 依据距离和密度聚类点 | eps/min_points受密度影响；本版未实现 |
| 形状补全/语义分割 | 推断轮廓或类别 | 引入模型假设和训练依赖；未实现 |
| 跨帧跟踪 | 连续关联同一物体/轴 | 遮挡、合并拆分需处理；未实现 |

形态学的操作对象是二值形状，不能证明补出的格是真实观测。若未来用来改善显示，
应明确区分“测量占用”与“推断轮廓”，不要悄悄让补洞结果提高分数或覆盖率。
DBSCAN官方接口示例见 [Open3D 点云聚类](https://www.open3d.org/docs/release/tutorial/geometry/pointcloud.html#dbscan-clustering)。

代码：v03.extract_regions 为形态学+外接矩形；v04.extract_regions 为稳定格连通区域+PCA。

# 10｜PCA 主轴、角度与 N/A

对区域内网格中心 q_i=(u_i,v_i) 等权求均值 mu，中心化后计算二维协方差：

```text
C = (1/N) * sum((q_i-mu)*(q_i-mu)^T)
C*v = lambda*v
r = lambda_max / max(lambda_min, epsilon)
theta = atan2(v_max.y, v_max.x) mod 180 degrees
显示角度 = (theta - 最长标定桌边角度) mod 180 degrees
```

最大特征值对应区域分布最分散的轴。项目用numpy.linalg.eigh处理对称矩阵。
一般原理参考 [OpenCV PCA 教程](https://docs.opencv.org/4.x/d1/dee/tutorial_introduction_to_pca.html)；
实际门槛以本项目pca_direction为准，不是OpenCV默认规则。

## 为什么 N/A 有时是正确输出

主轴跨度<5cm或r<2.5时，不输出角度。最新电脑区域r=1.609，所以N/A；
边缘小块虽然r=3.945，但跨度仅3.98cm，也N/A。区域仍可占用并参与分数。

r是特征值比例，不是准确率，也不是外接矩形边长比例。
对于理想均匀实心矩形，协方差比例约等于边长比的平方；有洞、不均匀或截断的实际区域不能直接套反推形状。
正方形两轴方差接近，轻微噪声就能改变“最大轴”，因此强制显示角度往往跳动。

## 常见角度陷阱

- PCA轴没有头尾，0°和180°是同一轴；179°到1°不能当178°大转动。
- 特征向量符号翻转正常，应按180°周期处理。
- 若将来平滑轴向角，应使用2倍角的sin/cos再折半，不能直接平均179和1得到90。
- 细长噪声也能有很高r，必须先保证区域可信；主轴稳定不代表轮廓完整。
- 参考桌边改变会改变显示角度；画布旋转不是物体相对桌面的旋转。

本版没有跨帧角度平滑或跟踪；是否放宽r门槛应独立验证，不能为了消除N/A而隐去不确定性。

# 11｜空闲度、占用率与质量门控

在active ROI内记F/O/U为空闲/占用/未知格，A=F+O+U。

| 指标 | 定义 |
| --- | --- |
| Visible free space | 100*F/(F+O)，只有质量通过才有效 |
| Occupied / known | 100*O/(F+O) |
| Occupied / active ROI | 100*O/A |
| Unknown / active ROI | 100*U/A |
| Stable known | 100*(F+O)/A，可含短暂历史 |
| Classified NOW | 当前有支持的已分类格/A |
| Held | 当前不支持该已知稳定状态的格/A |

例：60空闲、30占用、10未知，空闲度66.7、已知占用33.3%、全active占用30%、未知10%。
未知不能被补成空闲；排除带也不进入分母。小占用块即使没有成为区域/PCA，仍计入O。

## 有效显示条件

Temporal ON、未暂停；稳定已知≥90%、当前分类≥90%、Held≤10%。
失败时分数N/A、JSON null，同时显示原因。全未知不能得100分。
局部模式当前分类来自未经时间平滑的单格高度差，不能拿滤波后的历史结果冒充当前覆盖。

## 分数不回答什么

不回答物品摆得是否整齐、有无垃圾、是否好用、完整体积和遮挡后真实面积。
同一电脑旋转不因角度本身扣分，但投影/遮挡/格子量化可使检测面积略变。
READY也可能存在漏检：把真实电脑判成桌面时，分数会偏高。
因此可见空闲度是透明的代理指标，而不是“整洁程度真值”。

代码：desk_status_v05.measure、ScorePolicy、quality_inputs。PCA与区域数不参与分数。

# 12｜实验设计、独立验证和证据边界

## 拟合与验证要分开

C采集用于估计平面/空桌参考；V或重新启动后采到的新数据用于验证。
训练残差变小只能证明更贴合训练数据，不能证明以后也更准。
平面对照固定同一旧UV网格、同一ROI、同一批新原始点，避免“换检测范围”改变结果。
候选自己的坐标系用于实际运行，不把仅为比较构造的混合坐标表保存成标定。

## 指标要带上分母与样本条件

2026-11-01多帧平面验证中，共同可靠格4238，绝对高度中位数3.02→1.70mm，
P90 6.58→3.80mm；时间跨度中位数约6.84→6.84mm。
正确结论是参考偏差改善，而不是“所有误差减少”或“传感器精度提高”。

比较阈值先固定网格、机位、灯光和物体位置。比较灯光只改变照射条件，等待稳定。
不同位置或不同时刻的截图只能支持外观观察，不能直接计算召回率提升。

## 三层验证

- 单元/回归：边界、非法输入、数学、缺测、按键和文件不覆盖，证明软件规则。
- 合成生命周期：已知场景的放入、旋转、拿走、缺测，证明流程可复现。
- 现场：固定环境、明确物体和空桌、新数据持续观察，才能评估真实表现。

当前164项离线测试不替代真实帧率、连续稳定性、跨设备与干净机器安装。
参考采集成功、图像全绿、READY、PCA有值，任何一个都不是完整验收。

最小闭环：新空桌10秒 → 放物体10秒 → 旋转 → 拿走恢复 → 低观测质量时N/A。
记录失败场景比不断微调到某一张图好看更重要。验收标准是项目约定，不是行业认证。

# 13｜调参与排错：按依赖顺序来

| 症状 | 先看什么 | 避免什么 |
| --- | --- | --- |
| 还是旧画面 | 是否运行v05、是否传--background | 改了新文件却启动旧脚本 |
| 大片空桌持续红 | 同格高度中位数、平面/局部偏差 | 无限加宽边缘遮罩 |
| 红绿跳、覆盖仍高 | 时间P90-P10、门槛、Temporal开关 | 把覆盖率当精度 |
| 灰色增多 | 当前采样、参考有效性、深度范围 | 缺失值填0、降低评分门槛 |
| 薄电脑漏检 | 原始高度、局部变化、支持帧比例 | 先调PCA或连通组件 |
| 区域完整但N/A | reason、ratio、span_m | 强制输出不可靠角度 |
| 拿走后残影 | 当前证据、hold、时序年龄 | 继续加大窗口掩盖问题 |
| 参考拒绝加载 | 模式、哈希、网格/内缩、采样 | 手改JSON强行匹配 |

## 参数地图

- 默认绝对模式：--grid-mm、--min-height-mm、--max-height-mm、--edge-margin-mm。
- 时序与PCA默认值：desk_orientation_v04.Settings。
- 局部参考：desk_height_background.HeightPolicy；采集使用--seconds、--grid-mm、--edge-margin-mm。
- 显示质量：desk_status_v05.ScorePolicy；不是修复漏检的旋钮。
- 旧debug脚本仍有独立常量；修改它不意味着v05参数同步改变。

局部模式不会用--min-height-mm 3替换保存的逐格门槛；更改参考策略应重新采集和验证，
不要手改background.json。更换网格、内缩或标定需要匹配的新参考。

70分MVP的顺序：固定环境和机位 → 正确平面/ROI → 可解释采样和未知 → 合理分类 →
时序稳定 → 区域/PCA → 指标 → 复现/文档。先完成一个可信操作闭环，再考虑复杂识别。

# 14｜实现、文件格式、测试和发布

## Python / NumPy / OpenCV

- 点云用N×3数组，矩阵乘法一次计算高度与UV，布尔掩码过滤；避免逐点Python循环。
- np.floor处理网格索引，bincount聚合计数，排序/分位数计算单格统计；NaN表示没有有效数值。
- dataclass集中参数，validate拒绝非有限/非法值；各模块共享同一几何定义。
- deque保存有限历史，按时间过期；保存帧时复制数组，避免后续改写影响历史。
- contextmanager与try/finally释放相机/GUI；同一时刻只允许一个程序占用相机。
- GUI暂停保留画面但分数无效，恢复重置；headless与硬件入口分开以便自动化。

## 文件与可追溯性

calibration.json描述平面/坐标/ROI；candidate为另存候选；background.json是特定空桌参考；
report.json是结果摘要；samples.npz是逐帧网格统计，不是完整原始点云录像。
JSON缺测写null，严格禁止NaN常量；NPZ可保存NaN，读取使用allow_pickle=False。
以排他创建/新时间戳目录防覆盖，SHA-256绑定标定和参考的实际字节。

## 回归与复现

unittest覆盖三态、边缘、投票、PCA、分数、参考、生命周期、CLI和资源释放。
固定随机种子便于复现；训练与验证用独立噪声序列。测试只发现tests/，不批量执行硬件脚本。
依赖按离线、实时、四角标定、文档生成分层；版本范围不是跨平台锁文件。
已有环境测试通过不等于全新环境安装成功。

## 发布卫生

区分源码、历史实验、公共合成图、私有标定/截图/采集；.gitignore不删除本地文件，也不清理已提交的历史。
迁移应留清单/校验和，兼容链接不是备份。README给明确命令，不自动猜“最新标定”。
PDF复盘包含现场照片，公开前审查；作者自己选择许可证、账户和仓库可见性。

代码与操作见README、docs/INDEX及PROJECT_LAYOUT。不要为了目录漂亮而无验证重构运行依赖。

## 自测（答案提示）

1. 网格10mm，629格是多少？629cm²检测面积，不是体积或完整物体真值。
2. 空桌−4mm、物体后+4mm，差是多少？8mm；仍受测量偏差/波动影响。
3. 有100%覆盖为什么还漏检？高度可能低于门槛，覆盖不保证准确或正确分类。
4. r=3.9一定能出角度吗？不一定，还要看区域面积和主轴跨度等条件。
5. 179°和1°主轴差多少？按180°周期最小差2°，不能算178°。
6. 60空闲/30占用/10未知能得70分吗？按本定义是66.7，且还须质量门控通过。
7. 参考采集时忘拿电脑怎么办？清空重新采；不能用“成功保存”证明没有污染。
8. 新平面训练残差小是不是成功？还需新帧独立验证，再现场放入/拿走。
